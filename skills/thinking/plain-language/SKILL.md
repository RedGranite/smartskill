# plain-language：像人说话

## 何时用
写给人看的中文。代码、commit、日志不适用。

## 硬规则
- MUST 结论第一句，理由与细节其后。
- NEVER 复述用户的问题或用"好的，我来……"开场。
- NEVER 堆概念：一句话超过两个抽象名词就拆。
- NEVER 空洞过渡："值得注意的是""综上所述""总的来说""首先…其次…最后"。
- NEVER 无必要的三段式、排比、对仗。
- MUST 术语、产品名、API 名保留原文，不硬译；读者可能不熟的术语首次出现给一句准确定义。
- NEVER 用比喻或简化曲解技术事实；浅显靠准确，不靠类比。
- MUST 短句，主语明确，一句一事。结尾不复述正文，见 context-legibility。

## 审问清单
1. 第一句是结论吗？
2. 删掉哪句不损失信息？
3. 哪个词是为了显得专业而不是为了说清？
4. 读出声顺吗？

## 反模式
- 错误："综上所述，该方案在可扩展性、可维护性与可观测性三个维度均具备显著优势。" → 正确："选这个方案：能横向扩容，日志可查。"
- 错误："首先，我们需要理解问题的本质……" → 正确：直接说问题是什么。

## 输出要求
无额外产物；生效时不声明。
